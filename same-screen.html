Unreal Engine を AI に操作させたら、5時間で戦闘シーンができた。技術の話として読むと、いちばん重要なものを取り落とす。ゲームは、人とAIが「それ」と指させる最初の場所になりつつある。ただし、橋を渡れる人は限られている。

観察

5時間で起きたこと

新清士氏が ASCII.jp で書いている。Epic Games のゲームエンジン Unreal Engine 5.8 に、AI からアプリケーションを操作するための MCP（Model Context Protocol）が実験機能として入った。氏はそれを OpenAI の Codex から叩き、ロボットと戦車が戦うイベントシーンを作った。所要時間、約5時間。

内訳が面白い。1枚の画像から3Dモデルを起こし、Blender でパーツを分割して簡易アニメーションを付け、UE5 の Sequencer で動きを制御し、Niagara で炎と煙のエフェクトを作り、戦車にサーチライトを載せ、砲撃と爆発とレーザーを足していく。空全体を夕方にして、遠景にフォグをかける。

このうち、氏が自分の手で操作したのはオブジェクトの配置だけだ。Blender も Niagara も、開いてすらいない。Niagara の中身はまったく理解していないと本人が書いている。

途中、どうしても消えないデバッグ表示の赤い線が画面に残った。原因がわからず、AI に探らせた。Codex は UE5 のソースコードまで読み込み、1時間で Niagara の仕様に原因を特定している。氏は、人間が調べれば何日もかかる種類の問題だったと書いている。

技術的にはこれで十分すごい。だが、この記事の価値はそこではないと思う。

環境

ゲームは「現実マイナス2」である

前提をひとつ整理しておきたい。

「ゲームは現実に近いからAIが得意だ」とよく言われる。半分正しく、半分ずれている。正確には、ゲームは現実に近いのではない。現実から2つのものを引いたものだ。

引かれているのは、観測コストと不可逆性である。

現実世界では、いま何が起きているかを知ること自体に金と時間がかかる。ゲームエンジンの中では、全オブジェクトの位置も速度もマテリアルも光量も、すべて数値として露出している。観測コストはほぼゼロ。

現実世界では、失敗が残る。ゲームエンジンの中では消える。不可逆性がない。

そして、この2つを引いてもなお、空間と物理と因果の構造は現実と同型のまま残る。だからそこで得たものは現実へ転移しうる。ロボティクスの Sim2Real が成立するのは、この構造のおかげだ。

ここまでは、AIの側から見た話である。だが見落としてはいけないのは、引かれたその2つが、人間が何かを学べるための条件でもあるということだ。安全に失敗できない場所で徒弟は育たない。観測できないものから人は学べない。

ゲームは、人とAIが同じ条件下で動ける、いまのところほとんど唯一の環境である。

「架け橋として有望だ」という直感の根拠は、おそらくここにある。

本題

橋げたは言語ではなく、画面である

ただし、本当に効いているのはもう一段先だ。

新氏の作業ループを見てほしい。Codex は手順を Python スクリプトとして書き出し、UE5 に渡して実行する。結果をスクリーンショットで撮る。その画像を見て、意図どおりかを自分で判定する。そして人間も、同じ画像を見て判断する。

ここで起きているのは、単なる自動化ではない。共同注意（joint attention）だ。

トマセロは、人間の認知が他の霊長類から分岐した起点を、この能力に置いた。同じものを見て、指さして、「それ」で通じ合う。言語はそのあとに来る。共同注意が先で、言語は後だ。

テキストだけの対話には、これがない。言語は指示を運べる。だが指示対象を共有できない。「もう少し暗く」と言ったとき、私の頭の中の暗さとAIの頭の中の暗さが一致しているかどうかを、確かめる手段がない。

ゲームエンジンは、そこに参照点を置く。画面がある。両者が同じ画面を見る。「そこ」と指させる。

これが「架け橋」の実体だと思う。橋げたは言語ではない。画面のほうだ。

条件

渡れるのは、向こう岸を知っている人だけ

しかし同じ記事に、これを打ち消しかねない一文がある。

UE5 向けの MCP で何ができるかは、UE5 自体にどんな機能があるのかを理解していなければ、そもそも指示すること自体ができない——これは、いまから UE5 を使い始める人にとって課題になりそうだ。 新清士（要約）

具体的に考えるとわかりやすい。氏は Niagara を開いていない。中身も理解していない。だが「Niagara で炎を」と言うことはできた。Niagara というものが存在し、それがエフェクトを作る道具だと知っていたからだ。

知らない人は、その一文が言えない。

新氏は UE を使ったゲーム開発プロジェクトを3本経験している。VRゲームの開発を主導し、デジタルハリウッド大学院で教えている人物だ。だから指示できた。

橋は架かった。しかし渡れるのは、向こう岸に何があるかをすでに知っている人だけだ。

これは私がいま書いている本の中心的な論点と、正確に重なる。AIが奪ったのは仕事ではない。徒弟期間のほうだ。

かつて Niagara を覚える過程はこうだった。ドキュメントを読み、パラメータの意味がわからず1日つぶし、他人のサンプルを分解し、失敗を10回重ねて、ようやく炎が出る。その苦痛の全体が、「Niagara とは何であり、何ができ、どこが難しいか」という地図を、頭の中に描いていた。

いまは、その過程が5分に圧縮される。炎は出る。地図は描かれない。

ただし、ここは正確に言っておく必要がある。デバッグ線の一件が示すとおり、必要な地図の解像度は確実に下がった。Niagara の内部仕様まで知る必要はもうない。「赤い線が消えない」と言えれば足りる。

下がったが、ゼロにはならない。名前は知っていなければならない。地図の縮尺は粗くてよくなったが、地図そのものは依然として要る。そして地図を描いていたのは、圧縮されて消えたあの過程のほうだった。

これは能力の問題ではない。経路の問題である。

副産物

目的は、あとから生まれてくる

もうひとつ、拾い損ねると惜しい記述がある。

記事の中で、同じ構文が二度あらわれる。炎と煙のエフェクトを足したくなる場面と、戦車に発砲させたくなる場面。どちらも「こうなると……したくなる」という形をしている。

目的が先にあって、それを実現したのではない。できることが増えたから、欲望があとから生まれている。

これはサラスバシーがエフェクチュエーションと呼んだものの、教科書的な実例だと言っていい。手持ちの手段から始める（means-driven）。やっているうちに目的そのものが変質する（transformation）。5時間という数字も、許容可能な損失（affordable loss）の実測値として読める。

そしてこれは、フーコーの権力論に直で接続する。権力は奪うものではなく、作り出すものだという線だ。能力が増えると、その能力に対応した欲望が生成される。新氏は「戦車を発砲させたい」と最初から思っていたわけではない。発砲させられるとわかった瞬間に、思うようになった。

道具は、目的を叶えるためだけにあるのではない。目的そのものを生産する。
残る問い

橋は、まだ片側からしか架かっていない

この記事から取り出せるものは、三つある。

  1. ゲームは、人とAIが同じ条件で動ける環境である。観測コストと不可逆性が引かれ、構造だけが現実と同型のまま残っているからだ。
  2. ゲームエンジンは、人とAIのあいだに共同注意を成立させる。橋げたは言語ではなく、画面である。
  3. しかしその橋を渡るには、向こう岸の地図が要る。地図を描いていたのは、AIが圧縮してしまった徒弟期間のほうだった。

三番目が、いちばん厄介だと思う。

橋の技術的な部分は、放っておいても改善する。MCP はまだ実験機能で、UE5 のごく一部にしか手が届かない。これは1年で解ける種類の問題だ。

解けないのは、地図をどう描かせるかのほうである。苦労を経ずに地図を得る経路を、設計できるのか。それとも、地図を持つ最後の世代がいなくなった時点で、橋は誰にも渡れなくなるのか。

ゲームが人とAIの架け橋になるという直感は、正しいと思う。安全に失敗でき、すべてが観測でき、それでいて現実と同じ形をしている場所は、ほかにない。学びの条件と、AIの得意条件が、ここで一度だけ重なっている。

ただしその橋は、いまのところ片側からしか架かっていない。向こう岸に立てる人が、まだ橋を必要としない世代だけだからだ。
